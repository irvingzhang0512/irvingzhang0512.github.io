EMNLP 2026 | 代码Agent会写不会跑？RAT让GitHub仓库自动跑起来

要点

  • 痛点定位：环境配置是代码 Agent 执行任何软件工程任务的第一步，也是失败率最高的一步；README 过期、Dockerfile 缺失、CI 失效、多语言多包管理器混杂，导致简单执行 pip install 远远不够。
  • 方法三步走：①语言感知抽象（按 Python/Java/Rust/JS/Go 匹配专属依赖查找、包管理、排错逻辑）②ImageRetriever 用 LLM 语义分析 README 与配置，推断版本与框架，从标准镜像池选型并可按需检索 Docker Hub 打分选优 ③基于 ReAct 的迭代式排错，配套切版本、装依赖、解析 CI/CD、搜历史 Issue、生成冒烟测试等工具集，边错边改。
  • 评测与结果：构建 RATBench（2500+ 真实 GitHub 仓库，分层抽样覆盖语言/规模/配置完整度，以「真跑通构建与测试」为成功标准），ESSR 平均提升约 36.1%，优于通用 Agent（如 Claude Code），接近或超过资深工程师手动配置。
  • 延伸发现：增加计算预算时性能持续提升，呈现类似 scaling law 的曲线，而基线方法几乎无此规律，说明 Agent 设计质量决定了「算力—性能」增长关系；作者还强调该能力是代码领域强化学习、轨迹合成与执行评测的地基。
