hoja-work/hoja-claude-plugin

这是一个给 Claude Code 用的插件，核心机制是”任务不通过验证就不能标记完成”（task gate）+ Hoja/Trebol 工单同步，思路属于 Agent 可靠性治理，但项目极早期、几乎无社区验证。

✍️ hoja-work

要点

  • 技术亮点：把”完成定义（Definition of Done）”变成强制关卡——通过 Claude Code 的 hooks 在任务状态流转时拦截，要求提供证据（commit、测试结果、issue 链接）才能置为 done，并用 MCP 与 Hoja issue 双向同步；本质是给 Agent 加一道可验证的验收闸门，而非又一个 todo list。
  • 应用场景：适合你想约束 Agent”假装干完了”的老毛病——长任务、多步重构、需要跑测试才能收尾的场景；也可作为你自己写 Agent 编排时”结构化任务状态机 + 证据校验”的参考实现。
  • 社区趋势：⭐0、无外部使用者与讨论，属于个人/小团队早期实验品，接口与行为都可能频繁变动，不建议直接接入生产流程。
  • 风险提示：绑定 Hoja/Trebol 自有服务，插件与工单系统耦合较强，脱离该生态后价值有限；文档与验证案例不足，需要自己读源码判断可靠性。

⭐ 6.5 · 选读

GregoireF/kiwa

kiwa 是一个用 Rust 写的 CLI/TUI 任务运行器，它把多个项目、多个仓库（monorepo/workspace）里的所有 task 汇总成一份索引，并支持模糊检索；它还宣称可以让 AI Agent 通过 MCP 直接查找到并调用这些 task。项目想解决的问题是“Agent 不知道工程里有哪些可执行命令”。

✍️ GregoireF

要点

  • 技术亮点：采用 Rust 实现，提供 TUI 和 CLI，并集成了 MCP server；它把「按任务名模糊搜索 → 直接执行」做成一层跨项目的统一任务入口，思路是把 task runner 当作 Agent 发现工程中可执行命令的接口。
  • 应用场景：适合 monorepo 或多仓库开发者快速查找和运行命令，也适合作为 Agent 的工具层（tool layer），让 Agent 在进入陌生代码仓库时先“搜索可用 task”，而不是盲目猜测 npm scripts / make targets。
  • 社区趋势：项目刚起步，⭐0、无社区验证、维护与成熟度未知；它所属的赛道是“把 MCP 接入工程化工具链”，这个方向当下很热，但这个具体项目还只是概念验证级别。
