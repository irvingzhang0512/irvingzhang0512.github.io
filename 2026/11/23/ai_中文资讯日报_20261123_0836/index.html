Agent 接了上百个工具就变慢变贵？Gemini 把工具加载改成了按需检索

针对 Agent 挂载上百个工具后变慢变贵的问题，Gemini 把「全量加载工具定义」改为「按需检索工具」，本质是把 RAG 思路用到工具层。

📡 稀土掘金 人工智能频道 · ✍️ 可夫小子 · 2026-11-23 04:13

要点

  • 痛点：Agent 要真正干活，就要接 CRM、工单、邮件、数据库和多个 MCP 服务器；工具数一旦达到几十上百个，全部工具定义都塞进上下文，就会让 token 成本飙升、推理变慢，而且模型容易选错工具。
  • 解法：不再把全部工具的 schema 一次性放进 prompt，而是根据当前用户请求先做工具检索或召回，仅动态加载最相关的少量工具定义，相当于给工具做「RAG / 语义索引」。
  • 价值：上下文长度与成本随调用收敛，工具规模可扩展到上百而不再线性涨价；同时减少无关工具对模型选择的干扰，提升工具选择准确率。
  • 对 Agent 工程的启示：工具治理（命名、描述、分组、检索粒度）成为和 prompt 同等重要的工程环节，MCP 服务器多起来后尤其需要这套机制。
