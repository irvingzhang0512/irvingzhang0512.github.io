从模仿到自我纠错：Keeta客服模型的RSI实践

美团 Keeta 客服 Agent 用 CARE 闭环（上线巡检→归因定责→按事发 SOP 构造修复→在线自蒸馏 OPSD）做递归自我改进，五轮迭代把 31B 模型巡检 Bad Case 率从 6.42% 降到 1.97%，单均服务成本降 70.5%。

📡 美团技术团队

要点

  • 核心判断：RSI 的难点不在“学”而在“判”——错没错、错在谁（模型 vs 工具/SOP/组件）、按哪一版规则算错；因此巡检与归因由外部强模型承担，不让自研模型自评自判，避免强化自身错误。
  • 冷启动是数据治理问题而非单纯蒸馏：按完整会话做准入（语言/结构/语义筛查）、按地区组×场景×地区三层容量受限均分解决长尾淹没、再用人工客服会话只“借表达不借业务”做措辞精修。
  • 修复样本保留事发时的 SOP 上下文，一个训练集混合多个 SOP 版本，让模型学会“照输入里的规则办事”；OPSD 的特权信息是巡检归因结果，而非外部模型答案。
  • 结果与边界：冷启动后离线通过率 79%→93% 但线上 Bad Case 率反而 6.42% 高于基座与线上强模型，说明历史轨迹教不会模型避开自己引出的新错误；五轮迭代后 Bad Case 率 1.97%、满意度追平，配套论文为 CARE: Grounded Recursive Self-Improvement for Production Customer-Service Agents。

从 LOOP 到图探索 —— 算法模型的 AutoResearch 自进化系统架构演进之路

美团技术团队从 Karpathy 的 AutoResearch 出发，经过三次架构重构，把单线程「改代码—训练—看日志」LOOP 升级为 Spawn-Converge 图探索架构（CyclicGraph Engine），实现算法研究 Agent 的自进化，单任务耗时较人工基线降低 83%~85%。

📡 美团技术团队

要点

  • 起点是 Karpathy 的极简 AutoResearch 原型：program.md（自然语言研究规则）+ train.py（Agent 唯一可改）+ prepare.py（冻结的评估器），靠「裁判不可改 + keep/reset Git 棘轮」建立可信基础；搬到企业云端后暴露三个问题：自然语言规则不可信、环境异步差异、单线程 LOOP 只能维护一条时间线。
  • 三次演进路径清晰：V1 定时任务 + Shell 串行跑通（但上下文爆炸、状态不同步）；V2 拆成 Monitor/Iterator 双角色 + JSON 状态机（无状态触发 + 有状态文件，解决长会话上下文爆炸，为异步并行打底）；V3 打破 LOOP，主 Agent 拆分 3~4 个互斥假设派给子 Agent 并行验证，再收拢对比决策。
  • Spawn-Converge 的关键在「并行只是手段」：只并行不收拢就退化成多开实验；配套的是主 Agent 拆互斥假设 → 子 Agent 上下文隔离独立验证（防止彼此带偏）→ 主 Agent 汇总提炼洞察并决策下一轮。量化收益：同项目 LOOP 10 次迭代 3 天无突破，图架构 12 次迭代 4.7 小时（0.14 → 2.55 次/小时）。
  • 五条设计理念对 Agent 工程有普适参考价值：与 Agent 基座解耦（用 Harness 搭便车）、能代码表达的约束绝不写进 prompt（可信优先）、经验/工具/Skill 自动沉淀经人工校验回灌（越用越好用）、用真实上线大闭环回流知识库形成飞轮。

📡 V2EX 技术 · ✍️ lordmanderly · 2026-11-26 16:25

要点

  • 核心设计是把「收消息、判断归属」与「干活」拆开：Router（代码中叫 orchestrator）判断新事件属于哪个 Ticket，Worker 在独立上下文中推进，Trigger 和 Thread 分别表示进来的事件和同一话题内的连续事件。
  • 关键的工程取舍：状态全部保存到 SQLite，不依赖 Router 的上下文硬记；Router 通过分页读工具按资源路径取回上下文，超长的 Worker 汇报会被截断并附上读取指针，相当于把上下文窗口当作 cache 来管理。
  • 权限与成本控制：对外发消息的回复工具只挂载在 Router 上，并受引擎状态门禁约束；Worker 只能回一条简短接单确认；飞书等 IM 出口在发件箱代码中硬限 100 词。事件先经过确定性白名单和监听范围准入，只有仍需语义判断的候选事件才交给模型。
  • DeepSeek 给出了唯一公开的对照数据（合成负载、约 300 条消息、约 20 个工作请求、stub 执行，数据集未公开）：去掉「已订阅线程直通 Worker」后，完成时间不变，但 Router 决定次数增加约 30%，缓存读取从 2323 万涨到 3177 万 token（约 37%）。
  • 作者自己踩的坑：同一频道中的兄弟任务冲突、直接回复脱离追踪链、汇报合批增加延迟；这些都是单会话结构下不会出现的问题。

要点

  • 核心判断：命令式与工程化函数式的差别在于状态与控制流的组织方式，而 λ 编码（Church 编码）的额外成本来自「内置原语被替换」带来的间接层，两者不能混为一谈，也不能一概归因为「函数式对 AI 不友好」。
